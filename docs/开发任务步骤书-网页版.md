## 一、技术选型与总体架构

### 1.1 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | **React 18 + Vite + React Router**，纯 CSS（迁移 `styles.css`/`desktop.css` 的 CSS 变量主题系统） | README 明确推荐：原型即 React 思维编写，组件可近乎 1:1 迁移；无预处理器依赖 |
| 后端 | **Node.js 20 LTS + Express**（或 NestJS，团队熟悉哪个用哪个） | 契约为 REST/JSON；与原型同语言，字数计算等工具函数前后端可共享 |
| 数据库 | **MongoDB 6+**（Mongoose ODM） | 契约数据模型即 6 个文档集合（源自微信云开发），MongoDB 可 1:1 落地，索引建议照抄即可 |
| 鉴权 | JWT（Access + 可选 Refresh），bcrypt 存密码 | 契约 §2 |
| 内容安全 | **阿里云内容安全（文本审核增强版 Text Moderation Plus）**，敏感词本地库兜底 | 契约 §8 给出的首选方案之一，与部署环境同厂商，内网调用延迟低 |
| AI 灵感 | 服务端调用 LLM API：**阿里云百炼 DashScope（通义千问）** 为默认（境内服务器可直连）；预留 provider 抽象，可切 Claude API | 契约 §5：密钥只存服务端，限频 + 8s 超时降级 |
| 定时任务 | node-cron（进程内）；单实例部署下足够 | 契约 §9 三个 cron |
| 部署 | 阿里云 ECS（单机）+ Docker Compose（web/nginx + server + mongo）+ 阿里云免费 DV SSL 证书 | MVP 成本最低、路径最短；后续可平滑迁 ACK/函数计算 |

### 1.2 总体架构

```
浏览器（React SPA，静态资源由 Nginx 托管）
        │  HTTPS
        ▼
Nginx（443 终止 SSL；/ → 前端 dist；/api → 反向代理 :3000）
        │
        ▼
Node.js API Server（Express，JWT 鉴权，:3000 仅内网）
   ├── MongoDB（:27017 仅内网，开启鉴权）
   ├── 阿里云内容安全 API（UGC 落库前审核）
   ├── LLM API（AI 续写/润色，密钥仅服务端）
   └── node-cron（00:00 匹配 / 08:00 去年今日 / 09:00 不活跃检查）
```

### 1.4 全局开发约定（所有任务必须遵守）

1. 响应统一 `{ code, data, message }`；业务错误 HTTP 200 + 业务 code，鉴权失败 401，服务端异常 500（契约 §1）。
2. 错误码沿用 v0.2：`1001/1002/1003/1004/1005/9001/9002`（见附录 B）。
3. **服务端不信任前端**：字数（首封 150 / 回信 100 / 日记 30 / 评论 1–200 / intro 20–60）、标签数（3–5）、权限一律服务端复校；`word_count` 服务端重算。
4. 字数算法统一：去首尾空格，中文按字、英文按单词计，标点与空格不计（前后端共用同一实现，以服务端为准）。
5. 分页：`?page=0` 起，每页 10（评论 20）。
6. 日期：接口时间戳用 ISO 8601 `created_at`，业务日期 `YYYY-MM-DD`；「今天」以**服务端时间**为准（原型硬编码 2026-06-04 不得带入）。
7. 所有 UGC（信件、日记、评论、intro）落库前过内容审核：`pass` 放行 / `risky` 拒绝（1001）/ `review` 放行并标记待人工；审核服务异常时放行 + 记日志。
8. 权限矩阵（AI-Agent-SPEC §4.1，OPENID 替换为 JWT uid）：信件仅收发双方可读；仅收件人可置已读；情绪记录本人私有（public 的进广场）；他人资料只回安全字段。
9. 原型中的 `tweaks-panel.jsx`、`/*EDITMODE*/`、`data-screen-label`、`data-comment-anchor` 为设计工具痕迹，不带入生产。

## M1 数据库设计与建模

**目标**：6 个集合 + 索引落地，与契约 §10 / v0.2 数据模型逐字段一致。

### T1.1 集合定义（Mongoose Schema）

**users**（相对 v0.2 差异：`_id` 为服务端生成 uid；新增 `account` + `password_hash`）

```js
{ _id: uid, account /*邮箱或11位手机号，unique*/, password_hash /*bcrypt*/,
  nickname /*≤20*/, intro /*20-60*/, tags /*3-5个*/,
  active_time: 'morning'|'afternoon'|'night', letter_freq: 'weekly'|'biweekly'|'free',
  is_member: false, member_expire?, has_profile: false,
  created_at, last_active }
```

**letters**
```js
{ _id, from_uid, to_uid, parent_id /*回信指向原信*/, title /*≤30,可选*/, content,
  word_count /*服务端算*/, status: 'sent'|'read'|'archived'|'rejected', is_first,
  created_at, read_at? }
```

**drafts**
```js
{ _id, uid, to_uid /*可空*/, title /*可空,≤30*/, content,
  word_count, is_first, created_at, updated_at }
```

**moods**
```js
{ _id, uid, emotion: 'happy'|'calm'|'sad'|'anxious'|'mixed', intensity /*1-5*/,
  feeling /*可选,≤8字,细分词表软校验*/, visibility: 'private'|'friends'|'public',
  diary /*可选,填则≥30字*/, comment_count: 0, date /*YYYY-MM-DD*/, created_at, updated_at }
```

**mood_comments**
```js
{ _id, mood_id, from_uid, content /*1-200*/, parent_id /*顶层null*/, created_at }
```

**matches**
```js
{ _id, uid_a, uid_b, score /*0-100*/, tags_common: [], status: 'pending'|'active'|'skipped', updated_at }
```

### T1.2 索引（照抄 v0.2 末表 + Web 版新增）

| 集合 | 索引 | 用途 |
|------|------|------|
| users | `{ account: 1 } unique` | 登录/注册查重（Web 新增） |
| letters | `{ to_uid: 1, status: 1 }` | 收件箱 < 300ms |
| letters | `{ from_uid: 1, created_at: -1 }` | 已发出列表 |
| drafts | `{ uid: 1, updated_at: -1 }` | 草稿列表 |
| moods | `{ uid: 1, date: 1 } unique` | 月历查询 < 200ms；同人同日唯一（upsert 依据） |
| moods | `{ visibility: 1, created_at: -1 }` | 心情广场 |
| mood_comments | `{ mood_id: 1, created_at: 1 }` | 评论列表 |
| matches | `{ uid_a: 1, updated_at: -1 }` | 每日推荐 |

### T1.3 种子数据脚本

- 官方账号「**平常信使**」（匹配冷启动兜底 + 欢迎信发送方）；
- 2–3 个测试用户 + 少量信件/情绪/公开心情，供前端联调；
- `npm run seed` 幂等可重跑。

**验收**：Schema 校验拦截非法枚举/长度；`db.collection.getIndexes()` 与上表一致；seed 一键成功。

## M2 账号鉴权体系

**目标**：契约 §2 四个接口 + JWT 中间件 + 引导闭环。

| # | 任务 | 要点 | 验收标准 |
|---|------|------|---------|
| T2.1 | `POST /auth/register` | account 校验（邮箱格式 或 11 位手机号）、密码 ≥6 位；bcrypt(cost≥10)；查重（重复 → 业务错误）；成功即发 token + `hasProfile:false` | 重复注册被拒；库中无明文密码 |
| T2.2 | `POST /auth/login` | 校验密码 → `{ token, hasProfile }`；**登录限速防爆破**（express-rate-limit：同 IP + 同 account 双维度，如 10 次/15 分钟）；更新 `last_active` | 错误密码统一提示不泄露账号存在性；超限返回 429 |
| T2.3 | `POST /auth/logout` / `POST /auth/refresh` | MVP 简化：Access token 短时效（如 2h）+ Refresh（如 30d）；logout 将 refresh 加黑名单（Mongo TTL 集合即可，不引入 Redis） | 登出后 refresh 失效 |
| T2.4 | JWT 鉴权中间件 | `Authorization: Bearer` 解析 → `req.uid`；失效/缺失 → 401；除 `/auth/*` 外全部挂载 | 无 token 访问任意业务接口 401 |
| T2.5 | 引导门槛中间件 | `hasProfile=false` 的用户仅可访问 `/users/profile`（POST）与 `/users/me`，其余业务接口拒绝，防止跳过引导 | 未完成引导调写信接口被拒 |

## M3 核心业务 API

**目标**：契约 §3 路由总表全部落地。每个接口完成即用 REST Client/脚本自测正常 + 越权 + 边界三类用例。

### T3.1 书信（契约 §4）

| 接口 | 关键逻辑 |
|------|---------|
| `POST /letters` | 服务端重算 word_count；`isFirst=true`→≥150 / false→≥100，不足 → `1002`（message 带「至少需要N字，当前n字」）；过审核；`from_uid=req.uid`；**寄出成功后服务端删除对应草稿**（推荐方案）；对方拒收 → `1003` |
| `GET /letters/:id` | 仅收发双方可读，否则 `9001`；**收件人首读自动置 `status:'read'` + `read_at`**（仅收件人触发） |
| `POST /letters/:id/reply` | `:id` 为原信；校验回信人属于原信双方；写 `parent_id`；≥100 字 |
| `GET /letters/inbox?page=` | `to_uid=uid` 且过滤 `archived`；倒序分页；**服务端关联 `senderNickname`**；返回含 excerpt 所需字段 |
| `GET /letters/sent?page=` | `from_uid=uid`；关联 `receiverNickname` |
| `POST /letters/:id/archive` | 仅信件相关方；`status='archived'` |

### T3.2 草稿（契约 §4）

| 接口 | 关键逻辑 |
|------|---------|
| `POST /drafts` | 带 `id` 更新 / 不带新建；`targetUid` 可空（"还没想好寄给谁"）；草稿**不过**审核（未发布内容） |
| `GET /drafts?page=` | 返回 `{ _id, to_uid, receiverNickname, title, excerpt, word_count, required, updated_at }`；`excerpt` 服务端截取；`required` 按 is_first 给 150/100 |
| `DELETE /drafts/:id` | 仅本人 |

### T3.3 情绪记录（契约 §6）

| 接口 | 关键逻辑 |
|------|---------|
| `PUT /moods/:date` | `date=YYYY-MM-DD` 天然幂等 upsert；**服务端校验 `:date` ≤ 今天，且仅「今天」可写全量内容**（往日只能走 visibility 接口）；emotion 枚举 / intensity 1–5 / feeling ≤8 字且属对应词表（软校验：不属仅记日志不拒绝）/ diary 填则 ≥30 字并过审核 |
| `GET /moods?year=&month=` | 本人当月记录；月历、当月趋势（前端派生）、详情共用一个接口 |
| `PATCH /moods/:id/visibility` | 仅本人；public→非 public：**保留评论，仅从广场下架** |
| `GET /moods/memory-today` | 去年同日：优先 mood，无则 letter，都无 `data:null` |

### T3.4 心情广场（契约 §6）

| 接口 | 关键逻辑 |
|------|---------|
| `GET /plaza/moods?page=&includeSelf=` | 仅 `visibility='public'`，倒序；`includeSelf=false` 过滤本人；关联 `authorNickname`；含 `commentCount` |
| `POST /plaza/moods/:id/comments` | 目标须 public 否则 `9001`；1–200 字；过审核（违规 `1001`）；`parentId` 支持两级；写入后 `comment_count` +1 并回传 |
| `GET /plaza/moods/:id/comments?page=` | 每页 20，`{ _id, fromNickname, content, created_at, parent_id }`，前端按 parent_id 组装两级 |

### T3.5 匹配（契约 §7）

| 接口 | 关键逻辑 |
|------|---------|
| `GET /matches/daily` | 读当日 `matches` 中 `status='pending'` 按 score 倒序；**免费 3 / 会员 5**；用完 → `1004`；返回 `{ _id, score, tagsCommon, profile:{...公开字段} }` |
| `POST /matches/:targetUid/skip` | 对应记录 `status='skipped'`，当日不再出现 |

匹配分算法（`services/match.js`，供定时任务与冷启动复用）：

```
基础分 = |A∩B| / |A∪B| × 100   （Jaccard，按 tags）
+10 活跃时段相同  +5 书信频率相同  +8 对方7天内活跃
排除：已有通信关系 / 今日已跳过；上限 100
冷启动：可推荐 < 3 人时，插入「平常信使」补足到 3
```

### T3.6 用户（契约 §7）

| 接口 | 关键逻辑 |
|------|---------|
| `POST /users/profile` | 注册引导提交（对应原 createUser）：nickname ≤20 / intro 20–60（服务端复校）/ tags 3–5；intro 过审核；置 `has_profile=true`；重复提交 → `9001` |
| `GET /users/me` | 含聚合统计 `lettersSent / lettersReceived / moodDays`（后端算，勿信前端） |
| `PATCH /users/me` | 传啥改啥；intro 改动重新过审核；tags 改动影响下次匹配计算 |
| `GET /users/:uid/profile` | 他人公开资料：**只回安全字段**（nickname/intro/tags/active_time/letter_freq/last_active/isActiveRecently）；`recentExcerpt` 服务端截 ≤50 字 + 中文标签字段 activeTimeLabel/letterFreqLabel |

## M4 内容安全 · AI 灵感 · 定时任务

### T4.1 内容审核服务 `services/moderation.js`

- 接入**阿里云内容安全·文本审核增强版**（开通服务 → RAM 子账号 AK 最小权限 → SDK 调用）；
- 语义映射：厂商结论 → `pass / review / risky`；`risky` → 抛业务错误 `1001`；`review` → 放行并在文档上标记 `moderation:'review'` 待人工；
- **异常兜底**：审核 API 超时/报错 → 放行 + error 日志（与契约一致）；
- 本地敏感词库前置快筛（可选，省调用量）；
- 挂接点：sendLetter / replyLetter / saveMood(diary) / comment / users.profile(intro)。

**验收**：违规样本返回 1001 且不落库；审核服务断网时 UGC 仍可写入且有日志。

### T4.2 AI 灵感 `POST /ai/inspiration` / `POST /ai/polish`（契约 §5）

- provider 抽象层（默认 DashScope 通义千问，可配置切换 Claude API；**密钥仅服务端环境变量**）；
- 续写：服务端取该用户最近 ≤3 封已发信作风格样本拼 prompt → 返回 `suggestions` 3 条候选；
- 润色：`text ≥ 10 字`，不足 → `1002`「先写下一点内容，再帮你润色」；
- **限频**：每用户每日 N 次（默认 20，环境变量可调），超限友好提示；
- **超时降级**：8s 超时 → 返回友好文案（前端 toast），不报 500；
- 生成结果不落库；用户采用后随信件正常走审核。

**验收**：断网/超时不影响写信主流程；密钥不出现在任何前端资源与响应中。

### T4.3 定时任务 `jobs/`（契约 §9，node-cron）

| 任务 | 时间 | 内容 |
|------|------|------|
| dailyMatch | 每日 00:00 | 全量用户两两 Jaccard 计算（复用 T3.5 算法）写 `matches`，`status:'pending'`；排除已通信/已跳过 |
| memoryToday | 每日 08:00 | 找有「去年今日」记忆的用户 → MVP 仅记日志/站内红点占位，邮件通知可省 |
| inactivityCheck | 每日 09:00 | 识别 7/14/30 天未回应信件并标记（同 v0.2 №28） |

- 任务加分布式无关的**防重入锁**（单机内存锁即可）与执行日志（开始/结束/影响行数）；
- 提供 `npm run job:match` 手动触发入口，便于联调与补跑。

**验收**：手动触发匹配后 `GET /matches/daily` 出数据；日志可查每次执行结果。

## M8 阿里云部署上线

> 前置：T0.7 的域名备案已通过（若未通过，可先用 IP + 自签证书完成预发布演练）。

### T8.1 资源清单

| 资源 | 规格建议 | 用途 |
|------|---------|------|
| ECS | 2 vCPU / 4 GB / 40 GB ESSD，Ubuntu 22.04 LTS，按量或包月 | 应用 + 数据库单机 |
| 域名 | 主域 + `api` 可共用（Nginx 同机反代） | 访问入口 |
| SSL 证书 | 阿里云免费 DV（每年可申请多张）或 certbot | HTTPS |
| 内容安全 | 开通「内容安全-文本审核增强版」按量付费 | UGC 审核 |
| 百炼 DashScope | 开通并建 API Key | AI 灵感 |
| OSS Bucket（可选） | 低频存储 | MongoDB 每日备份归档 |
| 云监控 | 免费额度 | CPU/内存/磁盘告警 |

### T8.2 步骤书

**Step 1 — 服务器初始化**
1. 安全组仅放行 22（限自己 IP）/ 80 / 443；**3000 与 27017 不对公网开放**；
2. 创建部署用户、禁 root 密码登录（SSH key）；`ufw` 与安全组双保险；
3. 安装 Docker + Docker Compose plugin；配置国内镜像加速（阿里云镜像加速器）。

**Step 2 — 编排文件（`deploy/`）**

`docker-compose.yml` 三服务：

```yaml
services:
  mongo:
    image: mongo:6
    restart: always
    environment: [MONGO_INITDB_ROOT_USERNAME, MONGO_INITDB_ROOT_PASSWORD]
    volumes: [mongo-data:/data/db]
    # 不暴露端口到宿主机公网，仅 compose 内网
  server:
    build: ../server        # node:20-alpine 多阶段构建
    restart: always
    env_file: .env.production
    depends_on: [mongo]
    expose: ["3000"]
  nginx:
    image: nginx:stable
    restart: always
    ports: ["80:80", "443:443"]
    volumes:
      - ../web/dist:/usr/share/nginx/html:ro   # 前端静态产物
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./certs:/etc/nginx/certs:ro
volumes: { mongo-data: {} }
```

`nginx.conf` 要点：80 → 301 到 443；`/api/` 反代 `server:3000`（透传真实 IP 头，供限速用）；SPA 路由 `try_files $uri /index.html`；gzip；静态资源（含自托管字体）长缓存 + `index.html` 不缓存；`client_max_body_size 1m`。

**Step 3 — 首次发布**
1. 服务器拉取仓库（或 CI 推送产物）；
2. 配置 `deploy/.env.production`（附录 A，权限 600，绝不入库）；
3. 前端 `npm run build` 产出 `web/dist`（API base 用相对路径 `/api/v1`，无需区分环境域名）；
4. `docker compose up -d --build` → 跑 seed（仅建「平常信使」官方号，不放测试数据）；
5. 挂 SSL 证书（阿里云控制台签发下载 → `deploy/certs/`），验证 https 全绿；
6. 验证三个 cron 日志、健康检查、注册→写信全链路冒烟。

**Step 4 — CI/CD（可选但推荐，0.5 d）**
- GitHub Actions：push 到 main → lint + test → 前端构建 → 后端镜像构建推送**阿里云 ACR**（境内拉取快）→ SSH 到 ECS 执行 `deploy.sh`（pull 镜像 + compose up -d + 冒烟 curl）；
- 回滚：镜像按 git sha 打 tag，`deploy.sh --rollback <sha>`。

**Step 5 — 备份 · 日志 · 监控**
1. crontab 每日 03:00 `mongodump` → 压缩 → 上传 OSS（ossutil），保留 14 天；**演练一次恢复**；
2. Docker 日志 rotation（max-size 50m / max-file 5）；应用日志 pino → stdout 统一收集；
3. 云监控告警：CPU >80%、磁盘 >85%、进程存活（http 探测 `/api/v1/health`）→ 短信/钉钉；
4. 域名解析 A 记录 → ECS 公网 IP；备案号按规定展示在页面底部。

**M8 验收**：公网 https 域名可完成注册→引导→写信→收信→记心情→广场评论全流程；重启服务器后服务自动拉起（restart: always）；备份文件在 OSS 可见且恢复演练成功。
